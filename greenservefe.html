Explore greenServeFE
one file at a time.

greenServeFE (greenServe Fast Execution) is a C-based runtime that compiles .gsve programs into bytecode and executes them on a virtual machine. Browse the examples as file cards: click any filename to open its code.

Browse examples Source archiveRuntime releases
How it runs

Source → compiler → virtual machine

The lexer and parser process the language syntax; the compiler emits bytecode, and the VM executes instructions using values, environments and native functions.

1. Write GSVE

Save a program with the .gsve extension.

2. Compile

The compiler produces instructions, constants, names and child function code objects.

3. Execute

The VM runs bytecode with operand stacks, frames and lexical environments.

.gsve → lexer → parser / AST → bytecode compiler → GSCode → VM → output
Quick start

Build and run

Build the source archive on a Linux environment with the required native development libraries installed.

git clone https://github.com/MacoraOne/MacoraOne.git
cd MacoraOne/greenServeFE-source-codes-v1.0.3
make clean all
./greenServeFE test.gsve
./greenServeFE --dump test.gsve
./greenServeFE --trace test.gsve

The --dump option displays bytecode disassembly; --trace enables execution tracing. Follow the source archive and release README for dependencies and package installation.

Examples that import gsnum, gs_table, or server require the matching native module built for your greenServeFE ABI. Server examples need the server module and should be run from a directory containing any referenced static files or templates.

Runtime features

Language and VM capabilities

Values

Numbers, strings, booleans, null, arrays and objects.

Control flow

if, while, for/in, break and continue.

Functions

Function calls, recursion, closures and captured lexical environments.

Expressions

Arithmetic, comparisons, logical operators, assignment, indexing and member access.

Built-ins

print, len, str, num and type.

Debugging

Inspect generated bytecode with --dump and follow execution with --trace.

Native modules

Import functionality when needed

Native modules are shared libraries loaded by the runtime. The loader can search direct paths, the current directory, ./modules, and paths in GREENSERVE_MODULE_PATH.

ModuleExample usagePurpose
gsnumimport gsnum;Numeric helpers such as sum, mean and square root.
gs_tableimport gs_table;Render tabular data as text, CSV or Markdown.
serverimport server;HTTP routes, serving static files, responses, templates and outbound HTTP helpers.
Install the matching module shared library before running an import example. Module binaries must match the runtime's native ABI. Never commit private TLS keys or secrets into the source repository.
